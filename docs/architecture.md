# 아키텍처

## 페이지와 API

| 경로                                 | 역할                                                                                                                              |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| `/`                                  | 미팅 목록, 녹음 업로드                                                                                                            |
| `/meetings/[id]`                     | 미팅 상세. 본문에 제목(뒤로가기, 삭제 메뉴 포함)과 "노트" / "전사본" 탭, 우측 사이드에 날짜/참여자 편집. 녹음 재생은 전사본 탭 안 |
| `/settings`                          | 용어 사전 편집                                                                                                                    |
| `POST /api/meetings`                 | 녹음 업로드 → 미팅 생성 → 전사 시작                                                                                               |
| `GET /api/meetings/[id]`             | 미팅 JSON. 클라이언트 폴링용                                                                                                      |
| `POST /api/meetings/[id]/transcribe` | 전사 재실행                                                                                                                       |
| `POST /api/meetings/[id]/summarize`  | 요약 노트 생성/재생성. 전사가 `done`이 아니면 409                                                                                 |
| `GET /api/meetings/[id]/audio`       | 녹음 스트리밍. Range 요청 지원                                                                                                    |

페이지는 모두 `force-dynamic`입니다. 데이터가 요청마다 로컬 DB에서 읽히므로 정적 프리렌더를 쓰지 않습니다.

## 레이아웃

- 루트 레이아웃이 shadcn `SidebarProvider` + `AppSidebar`(`src/components/app-sidebar.tsx`) + `SidebarInset`으로 화면을 나눕니다. 사이드바 항목은 미팅(`/`, `/meetings/*`)과 설정(`/settings`) 둘뿐이며 `usePathname`으로 활성 항목을 표시합니다.
- 사이드바는 `collapsible="none"`으로 항상 펼쳐져 있습니다. 접기/트리거/모바일 시트를 쓰지 않기로 한 결정이라 상단 헤더도 없습니다.
- 미팅 상세의 두 탭은 모두 `keepMounted`로 항상 마운트해 둡니다. 다른 탭을 보고 있어도 전사/노트 상태 폴링이 계속 돌아 완료 시 화면이 갱신되게 하기 위해서입니다.

## 변경 경로의 경계

- 제목, 날짜, 참여자, 용어 사전, 삭제처럼 작은 변경은 서버 액션(`actions.ts`)으로 처리합니다. 저장 후 `revalidatePath`로 관련 페이지를 갱신합니다.
- 파일 업로드와 오디오 스트리밍은 라우트 핸들러로 처리합니다. 서버 액션의 본문 크기 제한과 스트리밍 응답 제약을 피하기 위해서입니다.

## 전사 파이프라인

1. 업로드 라우트가 파일을 `data/audio/<id>.<ext>`에 저장하고 미팅 행을 `pending`으로 만듭니다. 제목은 파일명에서, 날짜는 클라이언트가 보낸 파일의 수정 시각에서 가져옵니다.
2. 같은 요청에서 `after()`로 `runTranscription(id)`를 예약합니다. 응답은 즉시 돌아가고 전사는 서버 프로세스 안에서 계속 실행됩니다.
3. `runTranscription`은 상태를 `transcribing`으로 바꾸고, ffmpeg로 녹음을 10분 단위 모노 48kbps mp3 조각으로 나눕니다(`data/tmp/<id>/`). 전사 시작 시 읽은 용어 사전을 모든 조각과 재시도에 동일하게 전달합니다. `gpt-transcribe`에는 용어를 `keywords[]`, 언어 힌트를 `languages[]`로 보내고, 다른 모델에는 용어를 `prompt`, 언어를 `language`로 보냅니다. API가 거부하는 용어 내 `<`, `>`, 개행은 전송할 때만 공백으로 바꿉니다. 조각을 3개씩 병렬로 OpenAI에 multipart로 보내고, 순서를 유지해 합칩니다. 조각마다 최대 3회 재시도합니다.
4. 진행률(`done/total`)을 DB에 기록하고, 완료되면 `done`과 전사본을, 실패하면 `failed`와 오류 메시지를 저장합니다. 임시 조각은 항상 삭제합니다.
5. 상세 페이지의 클라이언트 컴포넌트가 3초마다 `GET /api/meetings/[id]`를 폴링하다가 전사 상태가 바뀌면 `router.refresh()`로 서버 컴포넌트를 다시 그립니다.

수 시간짜리 녹음이 흔하므로 10분 분할을 유지합니다. 작은 조각은 업로드 제한과 실패 시 재전송 비용을 줄입니다. ffmpeg가 없을 때만 25MB 이하 파일을 그대로 보냅니다. 전사 힌트의 필드와 제약은 [OpenAI 전사 가이드](https://developers.openai.com/api/docs/guides/speech-to-text)를 따릅니다.

## 요약 노트 파이프라인

1. 노트 탭의 "노트 생성" / "노트 다시 생성" 버튼이 선택 입력인 요약 요청사항을 JSON `{ userPrompt?: string }`으로 `POST /api/meetings/[id]/summarize`에 전달합니다. 본문 생략과 빈 문자열은 기본 요약으로 처리하고, 잘못된 JSON이나 문자열이 아닌 요청사항은 400으로 거부합니다. 라우트는 전사 완료 여부와 진행 중 여부를 확인한 뒤 `after()`로 `runSummary(id, userPrompt)`를 예약합니다.
2. `runSummary`는 상태를 `generating`으로 바꾸고, 시스템 프롬프트(`summary-prompt.ts`)와 미팅 정보 + 용어 사전 + 전사본 + 선택 요청사항을 담은 사용자 메시지로 OpenAI chat completions를 한 번 호출합니다. 요청사항은 전사본과 분리해 강조점·관점·상세도에 반영하되, 사실성과 기본 출력 구조는 유지합니다. 입력은 현재 화면에서 유지하며 DB에는 저장하지 않습니다. 기본 모델은 `gpt-5.6-sol`이며 `reasoning_effort: "high"`를 지정합니다. `temperature`는 지정하지 않습니다. 재시도는 하지 않습니다. 실패하면 같은 입력으로 사용자가 버튼을 눌러 다시 시도합니다.
3. 응답이 코드 펜스로 감싸져 오면 벗겨낸 뒤 `summary_versions`에 새 버전(v1, v2, …)으로 추가하고 상태를 `done`으로 바꿉니다. 실패하면 `failed`와 오류 메시지를 저장합니다.
4. 노트 탭의 클라이언트 컴포넌트가 `generating` 동안 3초마다 폴링하다가 상태가 바뀌면 `?v` 없는 URL로 바꾸고 `router.refresh()`해 최신 버전을 보여줍니다. 노트 본문은 서버 컴포넌트에서 마크다운으로 렌더링해 children으로 넘깁니다.
5. 이전 버전은 `/meetings/[id]?v=N`으로 봅니다. 없는 버전이나 잘못된 값이면 최신 버전으로 처리합니다. 버전 선택을 URL에 두는 이유는 서버 컴포넌트가 선택된 버전만 읽어 렌더링하게 하고, 특정 버전을 링크로 공유할 수 있게 하기 위해서입니다.

프롬프트는 `#### 개요` + 주제별 섹션, `*` 불릿과 명사형 종결을 유지하되, 짧은 종료 결정·현재 상태·역할·다음 행동을 긴 토론과 독립적으로 보존합니다. 개요는 여러 의제의 중요한 사실을 고르고, 제목은 구체적인 주제 라벨을 기본으로 합니다. 섹션별 불릿 수를 강제하지 않습니다. 이전의 "주장 + 근거", 결론형 제목, 수렴 중심 개요는 개별 사실을 누락하고 회의를 하나의 방법론으로 재해석하게 했기 때문입니다.

제안·개인 선호·반론·실행 동의·최종 합의를 구분합니다. 같은 주제의 발언을 모아도 새로운 절충안이나 팀 원칙을 만들지 않으며, 합의한 골격과 남은 세부 질문을 나눕니다. 미결은 실제로 제기되거나 보류된 사항만 해당 주제에 기록합니다. 숫자의 대상·조건, 사례의 현재 상태·이유, 단계별 범위·완료 조건·선후관계를 함께 보존합니다.

노트 생성에서 용어 사전은 STT 표기를 바로잡는 기준으로만 씁니다. 전사에서는 실제 발화에 나올 수 있는 표기 힌트이며, 등록된 용어가 반드시 출력되도록 강제하지 않습니다. 화자 이름과 역할은 확신할 때만 붙이고, 불분명하면 의견의 내용이나 대상 자체를 주어로 씁니다. 청크 경계나 인접 문장을 같은 화자·주제의 근거로 삼지 않습니다.

## 전사 상태 전이

```
pending → transcribing → done
                      → failed → (다시 전사) → transcribing
```

- `transcribing` 상태에서는 재실행 요청을 409로 거부합니다.
- 서버가 재시작되면 진행 중이던 작업은 사라집니다. DB를 여는 시점에 `transcribing` 행과 `generating` 행을 모두 `failed`로 바꾸고 재실행을 안내하는 오류 메시지를 넣습니다. 별도 작업 큐를 두지 않는 대신 이 복구 규칙으로 감당합니다.

## 요약 상태 전이

```
idle → generating → done → (다시 생성) → generating
                  → failed → (다시 생성) → generating
```

`generating` 상태에서는 생성 요청을 409로 거부합니다. `done`에서 다시 생성하면 새 버전이 추가되고 이전 버전은 그대로 남습니다.

## 모듈 책임 (`src/lib`)

| 파일                | 책임                                                              |
| ------------------- | ----------------------------------------------------------------- |
| `paths.ts`          | `data/` 하위 경로 상수                                            |
| `db.ts`             | SQLite 연결 싱글턴, 스키마 생성, 마이그레이션, 재시작 복구        |
| `meetings.ts`       | 미팅 CRUD와 전사 상태/진행률 갱신. 행 ↔ 도메인 객체 변환          |
| `settings.ts`       | 용어 사전 읽기/쓰기                                               |
| `summary-prompt.ts` | 요약 노트 시스템 프롬프트와 사용자 메시지 조립                    |
| `summary.ts`        | OpenAI chat completions 호출, `runSummary` 오케스트레이션         |
| `audio.ts`          | 확장자 판별, MIME/전사 포맷 매핑, 파일명에서 제목 추출, 저장 경로 |
| `audio-chunks.ts`   | ffmpeg 실행과 조각 파일 관리                                      |
| `transcription.ts`  | OpenAI 호출, 재시도, 병렬 처리, `runTranscription` 오케스트레이션 |
| `types.ts`          | `Meeting`, 전사 상태 타입                                         |

공용 UI는 `src/components`에 있습니다. `TagInput`은 참여자와 용어 사전이 같이 씁니다.
